# DSH GPT Companion Bridge Contract v1

Canonical implementation: `shared/bridge-protocol.mjs`. The bridge build copies it into its own `lib/`; Lead copies it to `desktop/shared/` for independent desktop packaging. No installation-time dependency on the project parent tree. Field signatures are frozen for runtime integration.

## Trust and transport

A standard DSH web client entry uses only its existing authenticated `ctx.connection.rpc.call('/api', 'codex-subscription/usage', {}, signal)` and read-only `codex-subscription/status`. Status reads bracket usage and must agree on exactly one active public account id. Only SHA-256 of `dsh-gpt-companion:<JSON([public-id, normalized-public-email-or-null])>` is persisted; public email is used only in client memory to fence identifiable account changes that reuse a vault slot. Account ids, labels, raw emails, credentials and arbitrary upstream error strings are never projected. This relies on the subscription plugin's public status semantics, not independent cryptographic provider identity verification: a same-slot replacement with no distinguishable public metadata cannot be independently detected by this bridge.

The client forwards the strict sanitized projection through its own `/api/gpt-companion/projection` route and acquires/releases a host-issued lease through `/api/gpt-companion/lease`. Both are exact POST routes registered on DSH Connection's `fetch` registry, behind DSH's existing authenticated owner-Peer admission. There is no host RPC call client, forged Peer, cookie/token copy, credential read, listener port or HTTP fallback. This package adds a loopback same-Host/Origin fence and disables its client on non-loopback/disconnected connections. DSH's HTTP bridge represents the internal request URL as `http://dsh.internal`; the actual admitted Host/Origin headers determine the local authority. An already owner-admitted owned-desktop request may omit Origin: the desktop shell deliberately strips Origin before authenticated loopback forwarding. In that case an actual Host header must be a strict localhost/127.0.0.1/[::1] authority with a valid port, with no userinfo/path/query/fragment. Missing Origin never authenticates a request. Present Origin still requires exact serialized same-origin loopback; cross-site is always rejected. SDK Connection's owner admission remains in front of every custom route.

Lease requests: `{action:'acquire'}` or `{action:'release',leaseId}`. A second client cannot steal a live lease. Projection payload: `{leaseId,seq,status}`; seq strictly increases within a lease. Late/replayed/revoked leases cannot restore an older account. These are standard DSH client-request/server-response envelopes, not a new authentication scheme.

## Files and envelope

Root: `<DSH_HOME>/state/dsh-gpt-companion/<profile>`, with DSH_HOME default `~/.dsh`, profile default DSH_PROFILE or `desktop`. Profile is a single `[A-Za-z0-9_-]{1,64}` component. Only fixed host-written `host.json`, `quota.json`, `completion.json`, `control-status.json`, `archive-status.json` and derived `numeric-logs/sessions/<epoch>-<logId>.jsonl` paths are writable by the bridge. The desktop alone writes the fixed bounded `desktop-control.json` described below. No caller-selected paths. Snapshots are UTF-8 JSON <=64KiB, logs <=256KiB each, at most64 active files; the separate archive budget is described below. Writes use exclusive random temp files, fsync and same-directory rename. Existing path ancestors/files must not be symlinks/junctions or non-regular redirected files. Files/directories request owner-only POSIX mode where supported; Windows inherits the user's DSH_HOME ACL. A process with the same user's filesystem authority can tamper with files: this is not a cryptographic or same-user adversary boundary.

All snapshots: `{schemaVersion:1,producer:'dsh-gpt-companion-bridge',instanceId,epoch,revision,lastSeenAt,expiresAt,hostActive,...}`. instanceId and epoch are UUID-shaped; revision increases within the host process. Times are integer epoch milliseconds unless explicitly stated otherwise. Heartbeat every 5s; host/completion TTL20s; quota/source/client lease TTL90s; future skew at most5s. Quota observation time comes from upstream fetchedAt, never a heartbeat. Missing/expired/malformed host, inactive host, different instance/epoch, invalid/expired quota or unverified identity mean unknown/disconnected, never 0%/100%.

`host.json`: envelope plus `{profile,connected,accountKey,numericLogs:[{file,bytes,sessionKey}]}`. accountKey is a SHA-256 fingerprint or null. file is a basename `<epoch>-<64hex-logId>.jsonl`; bytes is exact UTF-8 size; sessionKey is the owning real DSH-session hash. numericLogs is the sole allow-list (at most64): consumers do not recursively scan the bridge tree or access a database. Derived logs are synthetic exports, never claimed as original Codex logs.

`quota.json`: envelope plus `{status}`. status retains the normalized runtime shape `{ok,queryOk,source:'dsh',observedAt,accountKey,plan,planLabel,planKnown,planSource,authType,windows,errorCode?,error?}`. Windows are `[{kind?,label,minutes,used,remaining,resetsAt}]`. Percentages are finite0..100 and complementary; minutes is a positive integer (null for individual limits), resetsAt is epoch **seconds** or null. Codex rate-limit windows map from upstream `{windowSeconds,usedPercent,resetsAt}` with readable minute/hour/day labels. Business `individualLimit` is preserved as `{kind:'individual',label:'个人额度',minutes:null,used,remaining,resetsAt,total,amountUsed,amountRemaining}` from genuine service remainingPercent and bounded nonnegative decimal limit/used amounts (numbers or null in normalized output). Missing/invalid remainingPercent is unknown, never inferred from amounts. Individual-only responses can display without standard windows. Credits/cash/additional metered features are not mixed with subscription percentages. Failed/no-account status has no windows, plan or retained account. Public error strings are fixed, never upstream exception text. This version conservatively rejects non-whole-minute windows and missing active-account status rather than guessing.

`completion.json`: envelope plus `{seq,sessions,completion}`. seq increments only for observed live main-session turn/start followed by a successful completed turn/end; no replay, cancelled/error, seeded historical, subagent, parent-linked child or delegated session triggers. completion null or `{seq,sessionKey,turn,completedAt}`. Sessions at most64: `{sessionKey,title,active,updatedAt,usage}`. title is sanitized bounded public title metadata from the official projection (controls and recognizable credential-like strings removed), not messages. usage null or `{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens}`. inputTokens includes all input/cache buckets; outputTokens is separate. Usage covers live observations after the epoch baseline, not all historical account spending. seq is monotonic in one epoch; new epoch must be baselined without replaying its existing completion. Title/usage changes never manufacture a completion.

## Official usage, models and ledger exports

Host reads only the public `sessionProjections.snapshot(session,['tokenUsage','title','sessionStats'])` surface, plus lifecycle metadata on session/event and immutable header/firstLiveSeq. tokenUsage `{uncachedInputTokens,outputTokens,cacheReadTokens,cacheWriteTokens}` is authoritative. No message/stream body, prompt, tool result or raw source logs are copied or traversed by this package.

Per-model samples use live assistant/message's `message.source.{provider,model}` only. assistant/attempt lacks verified model metadata and is explicitly `unknown`, never guessed from the preceding model. The official cumulative projection handles retries; our last(turn,step) replacement slot removes its prior attributed sample before replacing it. `llm/retry-started` closes that slot so retries add rather than replace. For each bucket, the invariant is sum(epoch samples) == official cumulative - baseline. Missing projections, invalid/reset/mismatching counters or capacity failure yield null/unknown and no fabricated zero or financial estimate. Fork/resume/inherited history and account changes establish a new baseline, preventing inherited spending being charged twice. On account adoption the host sweeps the public `sessions.list()` and snapshots already-present sessions before their next settlement, so the first live post-connect sample is not swallowed by an after-the-fact baseline. This never replays completion events.

Logs are per-model **shards**, not independent chat sessions. logId = SHA-256(sessionKey:provider:model:internalSegmentId); filename contains epoch + logId. The opaque random segment id changes on bounded rotation, re-baselining or state recreation, so a later segment cannot transactionally overwrite already-imported older history. It is not an account/session identity and is not emitted as a separate field. Runtime must associate shards using `host.numericLogs[].sessionKey` and `session_meta.payload.session_key`, aggregate them for the real main-session card, preserve subagent cost attribution without inventing main cards, and rebuild/replace that shard's ledger records on content changes. Logs are atomic rewrites: append-only ingestion would double-charge corrected retry settlements.

Allowed JSONL records (integer millisecond timestamp):

- `session_meta`: payload `{id:logId,session_key:realSessionKey,origin:'dsh-gpt-companion-bridge',epoch,model_provider,source:'dsh'|'subagent'}`.
- `turn_context`: payload `{model,model_provider,turn_id}`; provider/model are bounded safe metadata ids; missing/unverifiable values are `unknown` (unpriced).
- `event_msg/token_count`: payload `{type:'token_count',info:{total_token_usage,last_token_usage?}}`; each usage contains only nonnegative safe integer `input_tokens,output_tokens,cached_input_tokens,cache_write_input_tokens,reasoning_output_tokens` (reasoning is0 because the official four-bucket projection does not report that separate subset).
- Reserved supported lifecycle `event_msg` types task_started/task_complete/turn_aborted, containing only `type,turn_id`.

No bodies, cwd, raw session ids, account ids, tokens or request headers. Numeric logs are bounded live telemetry, not a replacement for original Codex history. At most120 retained settlements/session/segment and64 active log shards. Rotation occurs only after the current retry/replacement slot closes; main-session epoch aggregate counters carry prior segment totals while the next segment exports only its own increment. Capacity failures/reset/missing-projection downgrade to unknown. Active files remain a bounded live cache, but task9 additionally preserves every accepted canonical numeric shard in the account-scoped durable archive below. Rotation/eviction/account changes remove only active files, not archives, so a closed panel can later catch up while the collector/identity lease was healthy. Budgets, dirty startup, storage/projection/coverage failures are explicitly flagged; the archive is not a claim to all DSH spending before collection began or outside verified collection intervals. Runtime must never price an unknown model or derive quota from tokens/cash.

## Account invalidation and lifetime

On receipt of account change, public-identity failure, invalid projection or disconnect notification: a new epoch, unknown quota, empty completion/sessions and empty log allow-list are written; prior exports are removed. Startup never reuses old files. Host disposal writes inactive/unknown. Abrupt exit is fenced by the20s host heartbeat TTL. A public-status poll starts roughly every30s with18s request deadline (visible quota poll60s, hidden no new quota queries): account changes outside this plugin become known on the next successful public identity read, not synchronously at another plugin's mutation. If connection loss prevents sending a notification, the old client lease and source observation expire within90s; the host then invalidates account/session data. Expired/failed quota by itself does not expire a separately verified identity or erase numeric history. No stronger real-time guarantee is claimed. Browser suspension/throttling is unknown after lease expiry, not fresh quota.

Reader sequence: bounded no-symlink regular-file read of host, verify fresh; read/validate quota and completion and cross-check instanceId+epoch; read only listed regular logs with exact bytes and validate; re-read host and require same epoch/revision as the start (or retry). This fences multi-file account-transition races without pretending three individual renames are one filesystem transaction.

## Shared API (stable)

- Constants: SCHEMA_VERSION, PRODUCER, MAX_SNAPSHOT_BYTES, MAX_LOG_BYTES, MAX_LOG_FILES, HOST_TTL_MS, QUOTA_TTL_MS, MAX_CLOCK_SKEW_MS, MAX_COUNTER.
- `validateHostSnapshot`, `validateQuotaSnapshot`, `validateCompletionSnapshot`, `validateQuotaStatus`, `validateUsage`, `validateProjection`, `validateProfile`: strict canonical copy or BridgeProtocolError.
- `parseSnapshot(text,kind)` with kind host/quota/completion: bounded parse + validation.
- `isSnapshotFresh(snapshot,now=Date.now())` and `snapshotsMatch(host,snapshot)`; call on already validated snapshots.
- `unknownQuota(errorCode='UNAVAILABLE',now=Date.now())`.
- `validateNumericLog(text,{epoch,sessionKey})` returns strict canonical records. Historical parameter name **sessionKey refers to the file's logId**, not its owner; owner is payload.session_key. Runtime also verifies this owner against the host entry.

## Consumer controls and real refresh (task6 additive v1 extension)

The desktop may write exactly one additional fixed file: `desktop-control.json`; all snapshots/ACKs remain host-written. Controls can be sent whenever hostActive and the host envelope are fresh, even without a signed-in account or connected client. No direct desktop HTTP or credentials are introduced.

Desktop control <=4096 UTF-8 bytes: `{schemaVersion:1,producer:'dsh-gpt-companion-desktop',instanceId,hostInstanceId,epoch,seq,issuedAt,expiresAt,active,visible,refreshSeq}`. instanceId is a per-desktop-process UUID; hostInstanceId/epoch must match the fresh host. seq increases for every write for the entire desktop process; refreshSeq increases only on explicit user refresh, coalescing older requests. A 5s heartbeat, TTL15s (maximum20s accepted), and `active:false,visible:false` on orderly disposal are required. Writers fence existing fresh owners and only write their own inactive frame on disposal after checking owner+host epoch; they never delete another owner's file. A fresh active owner cannot be stolen; inactive/expired ownership permits a new instance. No valid control means hidden. Replayed/modified same-seq frames do not renew ownership or reissue refresh.

**Required inactive-first scope handshake (task10 clarification):** A process-lifetime refreshSeq is not itself proof of a new click after a host restart/account epoch change. On every initial binding or hostInstanceId/epoch change, a legal writer first emits `active:false,visible:false` with its **unchanged existing refreshSeq** and incremented process seq. It waits for a fresh control-status envelope matching hostInstanceId+epoch, its consumer UUID and that refreshSeq, with control.active===false. The original host consumes an outstanding counter in an inactive frame as CONTROL_EXPIRED; an already consumed counter can retain another terminal/idle state, so the handshake does **not** require state=failed. Only after this baseline ACK may the writer publish its active visibility frame with the same counter. Explicit clicks arriving during the handshake are held in memory, do not increment refreshSeq yet, and increment/write only after the baseline is accepted. HOST_CHANGED cancels prior-scope click intents instead of migrating them. If scope changes again, ownership is not accepted, or the handshake times out, restart/fail the handshake rather than guessing from issuedAt. This is a legal-writer requirement compatible with the original host, not a new field or a claim that an arbitrary first active frame with a historical counter is automatically distinguishable. The inactive ACK must be causally generated **after** the inactive file write, not a cached active:false snapshot. With the current synchronous serial host publisher, a conservative field-compatible fence is: after the atomic inactive write, read host.revision as the baseline and wait for a matching control-status with revision>=baseline+2; two publications exclude the at-most-one older publish already in flight. A single revision increase can still be an in-flight pre-write publication. Late ACKs still cannot complete a runtime request with a different scope/counter.

New fixed `control-status.json`: normal host envelope (20s TTL) plus `{control:{consumerInstanceId,active,visible,refreshSeq,state,requestedAt,startedAt,completedAt,observedAt,retryAt,errorCode}}`. UUID/times may be null; idle has null consumer and zero refreshSeq. States: idle, queued, running, succeeded, failed, offline, timedout, rate-limited. ACK belongs to consumerInstanceId+refreshSeq+host epoch, never file mtime. Succeeded requires a real source observation; runtime also requires observedAt > its pre-request baseline and a valid matching fresh quota snapshot. Failed/offline/timedout are explicit, not success. Only the authenticated bridge client can complete a refresh ACK through a current host-issued lease.

The existing authenticated client polls `/api/gpt-companion/control` every5s. Payload `{leaseId,claimRefresh?:{consumerInstanceId,refreshSeq}}`. A claim succeeds only for the current visible consumer, pending request, current client lease and host-wide minimum10s force interval; newer clicks are coalesced, and no new usage query is made while hidden. Claim response `{ok:true,value:{visible,consumerInstanceId,refreshSeq,pending,retryAt,granted}}`. Running claims time out after30s if no authenticated completion arrives. Client quota polling is60s when visible, public status polling30s regardless of visibility to preserve verified account isolation/ledger scope. This adds no listener; DSH owns admission.

Projection is additively extended to `{leaseId,seq,status?,identity?,refreshResult?}`. At least status or identity is required; legacy status-only semantics remain accepted. identity is `{accountKey,observedAt}` from the official public status read (accountKey null when unverified). Verified identity renews the account lease independently of quota freshness: hidden/expired/failed quota becomes unknown without discarding a still-verified account or numeric history. Identity failure/change still invalidates prior account snapshots/epoch. status, if present, retains the original strict normalized schema; successful status must match identity. refreshResult is `{consumerInstanceId,refreshSeq,ok,observedAt,errorCode}` (observedAt/errorCode nullable); host verifies its current claimed sequence and lease before acknowledging. Client issues real `codex-subscription/usage` with `{force:true}` only for a granted manual refresh, otherwise `{}`. This force option is verified in installed subscription handler lines15945–15952 (`usageReader.read({force:payload?.force===true,signal})`) and bypasses its normal success cache; no undocumented option is invented.

Shared additions: DESKTOP_PRODUCER, MAX_CONTROL_BYTES, CONTROL_TTL_MS; `validateDesktopControl`, `parseDesktopControl`, `isDesktopControlFresh(control,host,now)`, `validateControlStatusSnapshot`; `parseSnapshot` additionally accepts kind `control-status`. All earlier snapshot field signatures remain unchanged.

## Durable numeric archive (task9 additive extension)

Fixed account-isolated flat directory: `archive/<verifiedAccountKey>/<originEpoch>-<logId>.jsonl`. No recursive conversation/data scan, title, body, raw user/session/account id or credential is archived. Files keep the exact numeric schema above, <=256KiB each, including the original header epoch/session_key. Every accepted canonical log is atomically written+fsynced to archive as well as the active cache. Clear/rotation/reset/account change/host restart and the64-active-log limit never delete archived files. The active log cap remains64; extra valid canonical shards still archive without corrupting official session totals. Collection requires a verified public account lease, not an open usage panel.

Readers may flat-enumerate only the current fresh verified host.accountKey directory, reject symlinks/non-regular/oversize files and names outside the strict UUID+64hex JSONL pattern, and process a bounded number/bytes per pass. Parse filename originEpoch/logId (not the current host epoch), validate the numeric payload against them, and use the same derived thread identity as the matching active shard to avoid duplicate billing. Revisit mtime/digest changes; archives are canonical rewrites, not once-only immutable imports. A **session_meta-only archive** is an explicit empty canonical/tombstone: a same-segment model attribution replaced by another route must retract the older thread's values. Metadata-only tombstones must transactionally replace old values with no events. Genuine segment rotation retains older valid data; it never emits a false tombstone for that spending.

`archive-status.json` is a new independent normal20s host-envelope snapshot, leaving all four prior snapshot signatures unchanged. Its `archive` object is `{accountKey,available,initializing,pendingFiles,collectionGap,firstGapAt,lastErrorAt,errorCode,totalFiles,totalBytes}`. Totals cover retained canonical files/bytes for the current account, not other accounts or token/cash totals. Unverified account means null key, unavailable and zero counts. Readers can still import retained validated files when collection has a gap; available/initializing/pending are not a completeness assertion. Display history syncing for initialization/pending and a persistent incomplete-history warning for collectionGap.

Persistent per-account `.collection-state.json` <=4096 bytes: `{schemaVersion:1,producer:'dsh-gpt-companion-bridge',accountKey,pending,collectionGap,firstGapAt,lastErrorAt,errorCode}`. It contains no text metadata. Known gaps are sticky across host/account epochs and restarts; successful later writes do not erase them. A prior pending marker on startup signals potentially uncommitted collection and becomes UNCLEAN_PENDING. No automatic purge clears history or silently claims recovery. Catastrophic inability to write even the gap marker is surfaced as unavailable/error while the host is alive; no guarantee is made that a physically unwritable filesystem can durably record its own failure.

Default numeric archive budget per profile, across its accounts:512MiB and65536 canonical files (small bounded state markers are separate). When a new/growing write would exceed the budget, old files remain untouched and the account gap is persisted as BUDGET_EXCEEDED. Shrinking canonical corrections may still commit; no old archive is silently evicted. Storage, unsafe index, queue, projection and session-capacity failures likewise mark explicit gaps. Startup scans are flat and incremental, at most128 entries per setImmediate batch, with O(1) indexed file/byte updates thereafter—not a global scan for every sample. Initialization coalesces at most128 pending files/8MiB; a durable pending marker precedes buffering, normal completion flushes in bounded batches, and overflow/dirty restart is a gap rather than falsely complete data. Session event handlers do not await a full-library scan. Live canonical writes keep the existing bounded synchronous small-file atomic/fsync behavior.

Shared additions: MAX_ARCHIVE_BYTES, MAX_ARCHIVE_FILES, MAX_ARCHIVE_STATE_BYTES; `parseArchiveFileName(name)->{originEpoch,logId}`, `validateArchiveState`, `parseArchiveState`, `validateArchiveStatusSnapshot`; `parseSnapshot` adds kind archive-status. Existing controls/host/quota/completion signatures do not change. This archive preserves numeric observations since enabled/verified collection, not historical conversations or unobserved pre-collection spending. An expired identity/no client can still interrupt collection; such unsupported intervals are not fabricated or priced from token guesses.

## Evidence and limits

Isolated tests cover strict fields/privacy, sizes/numbers/clocks, quota/account bracket races, lease replay, schema/account cleanup, main/sub/replay completion, retry replacement/multi-model conservation/fork baselines, missing-projection unknown, controlled disposal, path traversal/junction redirects, atomic IO, actual installed SDK request schema and internal HTTP URL shape, standard browser-loader exports, and a mock admitted client→registered route→filesystem→shared reader integration. Admission itself belongs to DSH and the mock is **not** proof of real authentication. Build/pack do not install or launch DSH. Real authenticated quota/session/UI integration remains deployment-only verification after separate user approval.
