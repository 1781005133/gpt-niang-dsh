# DSH GPT Companion — implementation rules

User approved an independent GPT/Codex dragon companion retaining all upstream GPT-Niang v1.4.0-beta.3 features. The source release archive SHA256 is 83085ec3661e654fc06d731ba2b39880412752af11fc15cc637f9b4276e70aba; source commit 285cb464ebc700be640ecc6a7be4ca3a05ba5371.

- Modify ONLY this project tree. NEVER modify installed DSH profiles, original whale/dragon plugins, installed codex-subscription, user credentials, or DSH checkout.
- Do not install, register startup tasks, restart DSH, or start another DSH server. Package/isolated tests are allowed. Deployment requires a later user confirmation.
- desktop/ is the independent fork. vendor/ contains immutable upstream reference source; audit/protected-files.json records original file hashes. Never modify vendor/.
- Identity: desktop package dsh-gpt-companion, version 0.1.0-beta.2, display name GPT龙娘 · DSH独立版. User program/state root %USERPROFILE%/.dsh-gpt-companion/{app,state}. AppId DSHGPTCompanion. Native binaries must use DSHDragon.{Start,Setup,Native}.exe and DSHDragon.Input.dll, with independent locks, titles, startup task/shortcut names and update identity. Keep original authors/license notices.
- bridge/ is a separate DSH bundle package dsh-gpt-companion-bridge version 0.1.0-beta.1, optional client dependency on @deepseek-ai/dsh-client-connection. Never copy/read tokens, cookies, auth.json, or bypass connection trust. Use legitimate client transport for codex-subscription/usage; host closure usageReader is not a public service.
- Bridge transport strategy: authenticated DSH client -> its own DSH authenticated RPC projection route -> sanitized per-user filesystem snapshots. Desktop reads snapshots, not DSH HTTP or credentials. No listener ports, no forged peers. Data root <DSH_HOME>/state/dsh-gpt-companion/<profile>; profile defaults to DSH_PROFILE or desktop. Disk files must be atomic, bounded, schema-validated and sanitized; no conversation bodies or credential fields. Empty/disconnected/expired data must not look like fresh quota. Account change/failure must not leak prior account snapshots.
- Shared contract is owned by bridge implementer in shared/bridge-protocol.mjs and docs/BRIDGE-CONTRACT.md. Runtime implementer coordinates with bridge implementer before adopting fields. Recommended quota output is upstream normalized status {ok,queryOk,source:'dsh',observedAt,accountKey,plan,planLabel,windows:[{kind?,label,minutes,used,remaining,resetsAt,...}],errorCode?,error?}, wrapped with schemaVersion, producer instance and last-seen time. Completion snapshots have stable seq/epoch and session identity. Numeric-only Codex-format export logs MAY be produced in a distinct subdirectory for reuse of upstream ledger; mark origin and never imply raw original logs.
- Preserve manual Codex data-directory selection and optional original Codex source. DSH is the default host/source for this new fork. No token->subscription percentage guesses, no cash/subscription mixing. Native audio/music and desktop/follow modes must remain available.
- Updater must NEVER download/install original GPT-Niang release. An unconfigured independent feed should be explicitly reported unavailable, not silently pretend update works; local verified package updates must remain possible.
- Scope ownership via shared tasks. No global formatters/replacers across another member's scope. Main Lead handles installer/identity scripts and top-level integration; runtime member owns runtime/, src/main.mjs, src/core/usage-service.mjs, src/usage-worker.mjs and associated source integration; bridge member owns bridge/, shared/; native member owns src/windows/, native/ and associated tests. Coordinate any other files.
